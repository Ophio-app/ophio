# Windows companion adapters

Windows runtime behavior is **partly qualified**. This code is cross-compiled on Linux. CI runs this crate's tests, including the Windows-only storage tests, on a GitHub-hosted Windows Server 2025 runner. The native test suite, the by-hand desktop tests and the packaged companion with a paired Android phone have also run on Windows 11 Enterprise LTSC 2024 (24H2, build 26100) in a virtual machine: one 1280×800 display at 100% scale on the Microsoft Basic Display Adapter, with a standard account and an administrator account. No physical PC, hardware GPU, second monitor, scale or rotation change, elevated application or Windows 10 has been exercised. [Windows 11 qualification](#windows-11-qualification) lists what ran and what has not.

The intended runtime target is Windows 11 x64 in an ordinary, signed-in interactive user session. No administrator rights, Session-0 service, driver, auto-login or window-isolation mechanism is used. UI Automation is used only by voice control, to read control names, roles and identifiers; it reads no text content. Product-owned code is Apache-2.0.

## API and integration

- `fs::{private_dir, private_open, protected_read, atomic_write}` create explicit protected DACLs with exactly the current user and SYSTEM. Existing objects must already meet that policy. Every path component is opened without reparse traversal and retained without delete sharing during leaf operations. Non-files, hard links, alternate data streams and non-local-volume paths are rejected. Reads enforce their bound even if a file grows. No permissive ACL is silently repaired.
- `dpapi::{protect, unprotect, SecretStore}` use current-user DPAPI with UI forbidden, a versioned envelope and stable application entropy. Identity plaintext is bounded to 64 KiB. Decrypted native allocations and Rust buffers are wiped on drop. The store creates secured temporary files and flushes before atomic replacement. Creation refuses an existing destination; rotation explicitly opts into replacement. Unprotected legacy identity files are rejected.
- `pipe::{OwnerListener, connect}` use a per-user pipe name from `ports::PROGRAM_NAME` and the current SID. The first instance reserves the name; each following accept creates its successor before releasing that reservation. Remote clients are rejected. The protected DACL admits owner + SYSTEM, but every connection additionally requires the peer process's token user to equal the owner. Both server and client verify their peer before application bytes flow. Clients prohibit server impersonation. No TCP fallback exists. The companion uses its existing bounded newline JSON framing and Hub caller boundary. The filesystem socket path argument has no effect on the Windows name.
- `startup::{install, uninstall, status}` implement HKCU Run registration plus an ownership marker. HKCU Run was chosen because it runs inside the user's logged-in session without elevation or a task-scheduler credential. Install registers the next logon; it does not itself start a process, restart crashes or run before login. The value uses `REG_SZ` and quotes the executable without a shell. Uninstall removes only matching owned values, preserving projects, accounts and unrelated startup entries. Status reports registration, not process liveness or the Windows Startup Apps enable/disable setting.
- `background::{own_console, keep_std_handles, elevated, Process}` let Øphio run without a window. `own_console` is true when Windows opened a console for this process alone, as it does at login or for a double-click in Explorer; `ophio run` then starts a windowless copy of itself and lets that console close. `keep_std_handles` clears the inherit flag on this process's standard handles, so a started copy cannot hold open a pipe a script reads the parent's output from. `elevated` reports an administrator's elevated token. `Process` holds a process handle so `service uninstall` can wait for the stopped companion to end even if its id is reused. `pipe::server_process_id` names the companion behind the owner pipe for that wait.
- `desktop::WindowsDesktop::new()` opts this process into per-monitor v2 DPI awareness and rejects an incompatible existing DPI policy or an elevated process. Construct it only after explicit desktop enablement, then give it to the control services; the backend itself does not grant leases. `with_driver` and `with_clock` provide deterministic test seams. The type implements `DesktopBackend`, `FrameStream` and `InputSink` through returned objects.

The companion uses these adapters end to end. `FileSecretStore` wraps identity and chat-token bytes with current-user DPAPI and uses the protected read/write functions. Config stays plaintext under the same explicit DACL and atomic replacement policy. Identity initialization is enabled; there is no plaintext fallback or automatic legacy-secret migration. Decrypted storage buffers, token input and `channels::BotToken` are zeroized.

After explicit desktop enablement, composition constructs `WindowsDesktop` with the shared clock. Native failures preserve unsupported, permission-missing, temporarily-unavailable or unknown capability states. Leases, grants and geometry checks still pass through the Hub. `DesktopSession::close` fences retained backend clones, closes capture workers and releases input even when consumers retain their streams/sinks. Failed releases are reported and can be retried. Native capture threads are joined on close/drop; their existing bounded frame waits can delay shutdown.

The CLI registers Ctrl+C, Ctrl+Break and console-close listeners before serving. On Windows it starts ordered shutdown concurrently with network draining and revokes desktop access before waiting for channel/agent cleanup. Console close remains subject to the [Windows OS termination deadline](https://learn.microsoft.com/en-us/windows/console/handlerroutine); forced termination and logoff/shutdown notification delivery are not claimed graceful. The owner-pipe client also handles bounded voice-progress replies.

The tool bridge resolves `computer-mcp.exe` beside `ophio.exe`, without searching PATH or the current working directory, and requires a regular file with an `.exe` extension on Windows. Composition supplies the bridge a boot-specific local named-pipe endpoint.

Native object names derive from `ports::PROGRAM_NAME`. `constants.rs` holds the DPAPI entropy, a persistent crypto context rather than branding: changing it requires an explicit migration, so it keeps its earlier label `host-companion.identity.dpapi.v1` across the program's rename.

## Capture and input behavior

WGC monitor capture runs on dedicated MTA threads with free-threaded frame pools and bounded request channels. D3D textures are copied through CPU staging textures into packed BGRA rows; native row padding is excluded. Cursor capture and the OS capture indicator stay enabled. A closed capture item invalidates retained frames. Each stream owns its capture history; cancellation resets damage history rather than passing hints based on a frame the consumer missed.

The process keeps one multithreaded-apartment usage for its lifetime (`CoIncrementMTAUsage`): the bindings cache WinRT factories process-wide, and without it the last capture thread to leave would tear down the apartment those factories belong to, so the next capture would call a released factory. An empty WGC frame pool ends the drain; the bindings report it as an error without a failure code. When Windows sends no new frame because nothing changed, the last picture is repeated with empty damage, so the encoder does no image work for an idle screen. That repeat tells the phone the picture is current, so it is only made after checking that the capture item still has the display's size and that its Direct3D device has not been removed or reset; otherwise the capture fails and the picture goes stale. DXGI's repeat after a wait timeout checks the device the same way.

DXGI Desktop Duplication is used when WGC is unsupported or its interfaces are unavailable. An access-denied WGC result is surfaced, never bypassed with another capture route. DXGI devices are created on the output's actual adapter. Dirty and move rectangles are merged; cursor changes damage both the old and new regions. Color, masked-color and monochrome pointer shapes are composed into the pixels. Rotated DXGI surfaces are oriented before delivery, with conservative full-frame damage. WGC and whole-desktop frames use full damage. Idle snapshots may repeat while the capture session and geometry remain valid.

Monitor geometry uses physical virtual-desktop coordinates with per-monitor DPI and rotation metadata. Whole-desktop capture preserves that physical layout, including black gaps; monitors are captured sequentially, so it is not a synchronized multi-GPU snapshot. Target IDs remain stable for the lifetime of the backend. Membership, origin, dimensions, DPI or rotation changes increase the geometry revision. Nonfinite, out-of-range, stale and gap coordinates are rejected. Capture rechecks geometry after collecting pixels. The input sink compares the complete geometry and the native layout before injecting.

Input uses SendInput absolute virtual-desktop coordinates at pixel centers, Unicode UTF-16 events, accumulated wheel deltas and explicit key/button tracking. Unsupported key names return a typed error; characters can use text input. Each action has a 250 ms monotonic insertion window, checked again after native target inspection so a slow sequence cannot keep adding input behind a pending revoke. A long action may be partially inserted before the window expires; it returns failure and must never be replayed automatically. A failed action stops that sink, attempts all releases and retains failed releases for retry/Drop. A new sink is required before more input. Native code verifies the interactive session, normal input desktop, foreground process integrity and mouse target integrity. A refused/short SendInput call never returns success. Native diagnostics contain fixed messages rather than text, pixels or Win32 error strings.

A classic console window (`ConsoleWindowClass`, as used by Windows PowerShell and Command Prompt outside Windows Terminal) drops Unicode keyboard events but still takes Enter and other keys. When one is in front, each typed character is pressed as its key on the console host's keyboard layout, with Shift, AltGr (Ctrl+Alt) and the current CapsLock state taken into account; a character on a dead key is typed as the dead key followed by Space. The layout is read from the thread that owns the console window's input context, because the window itself names its program's thread, whose layout can differ. Characters the layout has no key for and characters that need a dead-key composition, such as é on a German layout, stay Unicode events and are dropped by a classic console. With an East Asian IME open in a console, keys typed this way pass through the IME. The keys are looked up as if nothing else were down, so while Shift, Ctrl, Alt or a Windows key is held at the computer, typing into a classic console waits with `TemporarilyUnavailable` instead of typing another character or a shortcut; Øphio never lets go of the person's keys to type. Every other window, Windows Terminal included, receives Unicode events.

`PermissionMissing` identifies access/UIPI refusal, `TemporarilyUnavailable` covers locked/disconnected/unavailable sessions, and `GeometryChanged` covers stale coordinates. Windows cannot atomically freeze foreground focus around SendInput: success acknowledges OS insertion only, not delivery to a specific application. `lock_session` invokes LockWorkStation for the current session; the API acknowledges the request, not observation of a completed lock. `desktop_lock` reports the session's lock state from `WTSQuerySessionInformationW` (`WTSSessionInfoEx`), so a phone can show a completed lock; it reports unknown once sharing has closed or when Windows does not say.

## Verification

Linux tests additionally cover DPAPI envelope version/bounds, explicit create-versus-replace storage, token persistence, bridge filename/extension/endpoint rules, capability failure mapping and desktop close with retained consumers and failed-release retries. Linux tests cover mixed-DPI and negative-origin mapping, portrait orientation, geometry fencing, cursor blending/masks, damage clipping, composite gaps, stable catalogs, Unicode sequencing, wheel accumulation, release after partial failure, refusal propagation, strict SID parsing, protected SDDL, pipe-name isolation and startup quoting. They perform no desktop capture/input, account access or network calls. Windows-only storage tests use synthetic fixtures under fresh temporary directories; cross-compiling these tests does not run them, and the CI `windows` job runs them natively.

```sh
cargo fmt --all -- --check
cargo test -p platform-windows
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
# Cross-compiling needs the x86_64-pc-windows-gnullvm target and LLVM/MinGW (see BUILDING.md).
cargo clippy -p companion -p platform-windows -p computer-mcp --all-targets --target x86_64-pc-windows-gnullvm -- -D warnings
cargo build -p companion -p computer-mcp --target x86_64-pc-windows-gnullvm --release
scripts/package-windows.sh
```

Native Windows runs use the test executables cross-compiled with `cargo test --no-run --target x86_64-pc-windows-gnullvm`, copied to the Windows computer and run in the standard user's signed-in session; an SSH session has no desktop. The by-hand tests need the signed-in desktop and are skipped otherwise:

```powershell
.\desktop_native-<hash>.exe --ignored --test-threads=1 --skip taskbar_goes  # capture, Stop indicator, console typing
.\desktop_native-<hash>.exe --ignored taskbar_goes    # ends Explorer: run it last, restart Explorer afterwards
$env:OPHIO_DPAPI_FIXTURE = "$env:PUBLIC\fixture"      # readable by both accounts
$env:OPHIO_DPAPI_STEP = 'seal'                        # first account: seal, then open; second account: refuse
.\windows_storage-<hash>.exe --ignored
```

The llvm-mingw release linker warns about an unused `-no-pie` argument; the warning is harmless. Whole-workspace Windows Clippy encounters the Linux-only `wayland-sys` dependency; use the scoped Windows command above to check all targets of the three shipping crates.

Direct dependencies: `windows = 0.62.2` (Microsoft, MIT OR Apache-2.0) and `zeroize = 1.8.2` compatible range (MIT OR Apache-2.0). Microsoft windows-* support crates use MIT OR Apache-2.0. Versions resolved for a particular build are in Cargo.lock. No native terminal dependency is added; terminal ownership stays in the terminal crate.

## Windows 11 qualification

### Run on Windows 11 24H2 in a virtual machine

- All 38 test programs of `companion`, `computer-mcp`, `platform-windows`, `services`, `library`, `harness-claude`, `harness-codex`, `ports`, `terminal`, `browser`, `containment` and `media` pass natively in a standard user's signed-in session. The run found Windows-only defects that are fixed: `uninstall-data` deleting its own open lock file, phone-visible paths mixing `/` and `\`, and the pseudo-console's start-up cursor request (see the terminal crate).
- DPAPI across accounts: a fixture sealed by one account opens for that account and is refused to a second account whose own DPAPI works, after the copy is stored in a directory the second account owns.
- Owner pipe: the owner gets replies; the administrator account, connecting from its own SSH session, is refused by the pipe's DACL (a second standard account was not tried); SYSTEM, which the DACL admits, is disconnected by peer verification before any reply.
- Install from the ZIP into a folder with a space after Unblock-File: `service install` starts the companion at once with no window and survives closing the terminal; it is listed as ophio under Settings › Apps › Startup; after a restart it starts at login with no console; `service uninstall` stops it in under 0.3 s so the files can be replaced; an administrator terminal is told it starts at the next login; a script capturing `service install` output returns; a second `run` exits quietly or reports the data in use; a double-click explains setup. Allowing the companion through Windows Firewall needs an administrator, and a declined prompt adds Block rules that override later Allow rules (see the install guide).
- Ctrl+C, Ctrl+Break and closing the console stop an idle, paired `run` with exit code 0 within 0.1 s and free the port; a restart after a forced kill works.
- Paired with an Android phone by link, with the code confirmed on the computer; the QR printed in a classic console decodes to the same offer from a screenshot, though no camera scanned it there. Through the phone: a PowerShell terminal in a project folder with Unicode, history recall and reattach; a 3 MB upload and download with matching SHA-256; project file download; desktop sharing turned on and off reaching the phone live; watching; Take over; typing into classic Windows PowerShell on en-US and de-DE layouts (AltGr, dead keys, umlauts, €, CapsLock) and into Windows Terminal; Lock desktop showing as locked with input off; recovery after unlocking with input paused until Take over; a screen left completely still, watched for 25 s, stayed current on the phone.
- By hand: repeated still and live capture of the display; typing into a Command Prompt it opens, which waits while Shift or Ctrl is held and then types mixed case and shifted symbols as sent (five runs in a row, no key left down); the notification-area Stop showing, staying unpressed and showing again for the next grant, including while Windows keeps it among the hidden icons; Stop firing when Explorer ends.

### Still unqualified

- Independently inspect file/directory DACLs and test junctions, symlinks, inherited/extra ACEs and parent rename races. Through the actual companion, inspect every temporary/final DACL for exactly owner + SYSTEM; test failed write/rename/crash and create-new collision.
- Bridge discovery: start `computer-mcp.exe` beside `ophio.exe` from an agent run; remove/rename it or replace it with a directory/non-exe and verify honest unavailability. No agent ran on the virtual machine.
- Ctrl+C, Ctrl+Break and console close during capture, held input, an active bridge and slow channel/agent shutdown. Forced kill and user logoff/shutdown need separate lifecycle evidence.
- Owner pipe: concurrent connections and reconnects, a remote client, a killed connecting client, and a same-user client impersonating the server's account.
- Windows Startup Apps disablement, foreign Run-value protection and repeated install/uninstall across logons.
- Capture on two monitors, mixed 150%/100% DPI with negative origin, 90/180/270-degree rotations, HDR, a hardware GPU, cursor crossings and whole-desktop temporal skew. DXGI Desktop Duplication has not run; force it through a qualification-only driver choice or an environment where WGC is unavailable, and check dirty/move/cursor damage against full frames.
- Changes of scale, resolution, rotation, monitor membership and primary display during capture and input; session disconnect/reconnect and graphics-device loss.
- Pointer input from the phone: corners, dragging, modifier chords, scrolling and releases after drop/error, compared against the captured pixel on every monitor. Typing in a classic console with an East Asian IME open.
- Refusal over an elevated application, the UAC secure desktop and a disconnected session, including mid-chord transitions and release retry.
- Lease expiry, cancellation during frame acquisition and concurrent watchers.
- Windows 10, a physical PC and git or Tailscale installed alongside the companion.

Reference behavior: [SendInput and UIPI](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput), [Desktop Duplication rotation, damage and pointer semantics](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api).

## Local archive

Run `scripts/package-windows.sh` from a Linux build environment with the Windows GNU LLVM target and llvm-mingw configured. It builds both binaries with `--locked` and assembles `dist/windows/ophio-<version>-x86_64-windows.zip`. It contains `ophio.exe`, `computer-mcp.exe`, the Apache-2.0 LICENSE, the generated NOTICE and THIRD-PARTY-NOTICES.txt, the SBOM (`sbom.cdx.json`), `license-report.json`, the usage guide `INSTALL.md` from `packaging/windows/` and the SHA-256 manifest `SHA256SUMS`. There is no installer, signing or upload.

The ZIP uses sorted entries, fixed permissions and `SOURCE_DATE_EPOCH` timestamps (default: current commit timestamp); identical inputs and Python/zlib versions yield identical archive bytes. Bit-identical compiler rebuilds across different paths/toolchains remain unqualified.
