# Linux desktop adapters

`LinuxDesktop::detect(&Environment)` is pure: the caller supplies session information and the advertised Wayland globals. Native capture plus virtual pointer/keyboard is preferred, then the desktop portal on Wayland, then X11 on X11 sessions. Every implemented input route affects the session's focused target; none claims per-window isolation.

The composition root explicitly supplies a `Driver`, capability snapshot, and optional `SessionLocker` to `LinuxDesktop::new`. Driver construction never guesses a Wayland socket or X11 display. `WaylandDriver::new` takes an absolute socket path, `X11Driver::connect` takes an explicit display, and `PortalDriver::request_consent` takes an existing D-Bus connection and `TokenStore`. Only the last operation initiates portal consent. After successful portal consent, the driver reports Available; its session-closed listener changes that to Revoked. Retain the portal driver to call `close()` when desktop sharing ends.

Targets have stable per-backend identities and a monotonic geometry revision. Changes in output membership, position, dimensions, scale or rotation invalidate old input. Multi-output targets compose in a common logical layout at the highest output scale. Input coordinates use the same layout. Invalid, nonfinite and stale coordinates are rejected. The input sink tracks held keys/buttons and attempts every release even if one fails. Native Wayland and X11 input objects also release held state when dropped. Native error text, typed text, image data and restore tokens are never logged by this crate.

Implemented native paths:

- wlroots screencopy with SHM buffers, cursor embedding and per-stream damage. Still captures use immediate copy; streams use copy-with-damage and, when nothing has changed for 750 ms, fall back to an immediate copy, so a still screen keeps arriving at viewers that treat silence as a stall. Capture streams have independent protocol contexts. `ext-image-copy-capture-v1` with output capture sources is also supported; it currently requests complete buffers for each frame. xdg-output supplies fractional-scale geometry when advertised. Virtual pointer uses fixed-point normalized coordinates; virtual keyboard builds XKB keymaps for Unicode keysyms and restores depressed modifiers when expanding the map.
- Portal ScreenCast + RemoteDesktop through ashpd, with persistent permission mode and restore-token rotation. PipeWire streams negotiate packed RGB/BGR formats, keep a single latest sample, read supplied damage/cursor metadata, and request damage metadata. Skipped samples invalidate damage hints. `FileTokenStore` atomically writes owner-only files under a supplied data directory and rejects symlink reads. Its directory must be owned and protected by the companion.
- X11 GetImage capture, RandR output enumeration, XFixes cursor composition, and XTest input. Character mappings use existing level-one keysyms or temporary unused keycodes, restored on release and drop. X11 wheel events accumulate continuous deltas in 15-unit steps. GetImage is the portable fallback; MIT-SHM acceleration is not implemented.
- Session locking invokes `loginctl lock-session` with a validated explicit session identifier, through an injectable `SessionLocker`.

Verification uses a private in-process Wayland server and synthetic pixels/events; tests do not discover a real display or call the desktop portal. Run with `WAYLAND_DISPLAY`, `DISPLAY`, and `DBUS_SESSION_BUS_ADDRESS` unset. Portal and X11 native interoperability, compositor-specific consent persistence, lock/revoke behavior, rotated and fractional-scale outputs, and performance still require isolated desktop VM qualification. The fake compositor validates protocol mechanics, not GNOME/KDE/Hyprland/Sway release compatibility. No native X11 or portal integration result is claimed here.

Versions are explicit in Cargo.toml. PipeWire requires its development library and libclang at build time; native runtime libraries are supplied by the host distribution. Product-owned code is Apache-2.0.
