# Voice control

Voice control lets you say what to do in a browser or on the desktop, and Øphio does it. TypeSafe's Jev works out what you meant from what you said and the controls on screen.

Link your own TypeSafe access on the computer with `ophio jev connect`. Enter the key at the hidden prompt, or supply it through standard input; never put it in command arguments. Øphio stores it in its protected data directory (0600 on Linux, user-bound protection on Windows). The phone receives only whether Jev is linked. The CLI explains what is sent and how it is charged before storing the key. `ophio jev status` reports the locally known state without contacting TypeSafe. `ophio jev disconnect` removes the saved key, and voice control stops until Jev is linked again. “Linked” means a protected key is stored; access is tested only when a voice command asks Jev.

Charges go to your own TypeSafe access and are separate from Claude and Codex subscriptions. The session receipt reports Jev's token usage when returned; it does not estimate a price. Consult [TypeSafe's model pricing](https://docs.typesafe.ai/models) for current rates. Requests go directly to TypeSafe. TypeSafe and its service providers process them according to [its privacy policy](https://typesafe.ai/legal/privacy-policy). TypeSafe says it does not train on input, but ordinary accounts do **not** have a zero-retention guarantee; see [data processing terms](https://typesafe.ai/legal/data-processing) and [the retention overview](https://docs.typesafe.ai/legal).

Øphio pins **TypeSafe SystemOne v1**, endpoint `https://api.typesafe.ai/v1/systemone`, and model `jev-1.13.0` together. It uses a Bearer key, refuses redirects and does not retry requests. The [direct API reference](https://docs.typesafe.ai/api) documents this contract.

## Using it

Browser voice control needs Jev linked. Desktop voice control also needs the computer's desktop input (`ophio desktop enable`); it does not need the app in front to expose its controls. Each has its own switch in **Settings › Data and voice › Voice control**. Disconnecting Jev, or TypeSafe refusing the key, makes voice control unavailable until Jev is linked again. A slow, busy or unreadable answer fails only that command; the next one asks again.

### What you can say on the desktop

- **Open an app**: “open the browser”, “open a terminal”, “open the file manager”, “launch Telegram”. The words after “open”, “launch” or “start” are matched on the computer against its own installed apps (desktop entries on Linux): by name, generic name, keywords or program name, allowing a misheard letter. “The browser” is the desktop's default web browser (its `x-scheme-handler/https` default); “a terminal” is the one the desktop names, checked in this order: the program Hyprland binds to Super+Return, `xdg-terminals.list` (xdg-terminal-exec), KDE's and Xfce's terminal settings, `$TERMINAL`, the desktop's own terminal (Ptyxis, Console or GNOME Terminal on GNOME; Konsole on KDE), then a well-known installed one. When several apps match equally, say or tap 1–3. The app list never leaves the computer: Jev hears only that you asked to open something.
- **Go to an address**: “go to example.com” opens `https://example.com` in the default browser.
- **Press keys and shortcuts**: “press Enter”, “press Escape”, “press Super Enter”, “press control shift T”, “press alt F4”.
- **Type**: “type hello world” types into the focused app, as the remote keyboard would. Speech recognition ends sentences with a full stop; one at the end is dropped unless the text is in quotes.
- **Scroll, go back or forward, switch tabs**: “scroll down”, “scroll up”, “go back” (Alt+Left), “go forward” (Alt+Right), “next tab” (Ctrl+Tab), “previous tab”.
- **Click by name**: “click Sign in” needs the app in front to expose its controls through accessibility (AT-SPI on Linux). Many apps only do that when accessibility is turned on, and many terminals never do. When nothing can be read, Øphio says so; everything above still works.

- **Anything else**: a request that needs several steps (“open Firefox and search for cats”, “find my latest invoice and open it”), or a click on something Øphio can't read, can go to a computer-use agent. The phone shows the exact words the agent gets, the agent it would use (the one Start computer use would choose, with its default model), the display and the project chosen in Control. Nothing starts until you tap **Hand to …**: voice control then stops and lets go of the display, and computer use starts on it with your words as its instruction, exactly as Start computer use would, with Stop on screen. Computer-use agents open apps with the same app list and launcher, through their `open_app` tool, under their own agent lease; power, session and removal tools are left to you. It is offered only when the computer can run computer use and this device may start it; otherwise, and on older phones, you see the plain refusal (“This needs several steps. Say one step at a time…”).

Opening an app needs the same authority as opening it from Apps and windows: an active control lease from this device. Apps open in their own systemd scope under the session's `app.slice`, so restarting or updating Øphio never closes them. Opening apps by voice is built for Linux; on Windows and macOS it says so and the other commands still work.

Commands are confirmed first when they could submit, close, quit or delete: Enter, Delete and Backspace on their own or with Ctrl, Alt or Shift; Alt+F4; Ctrl, Alt or Super with W or Q; Ctrl+D; Super+M and Super+Shift+E; apps whose names are power, session or removal tools (shut down, reboot, log out, uninstall); and anything Jev judges consequential. For a key or shortcut, Jev's judgement counts only when it is sure (0.9), because it can't know what a desktop binds its shortcuts to and calls most of them consequential when unsure.

Only the finished command is interpreted: words still being spoken are shown on the phone and never sent to Jev or acted on.

Open Control → Voice control and choose a target, or use Voice in a display's live desktop view. The start sheet explains the separate browser profile, computer takeover and data sharing. Preview mode is selected initially and sends no input. The local speech recognizer supplies text; a typed command is also available. Install a local speech model through Data and voice to enable speech. While voice control runs, the live desktop view only watches: touch input from that device is off, and leaving or hiding the view does not end the session. Stop voice returns touch and keyboard input.

Voice interpretation sends the transcript and the names, roles and identifiers of at most 100 controls to TypeSafe. It does not send screenshots, field values or general page text. Charges use the person's own Jev access. Transcripts, validated answers, actions, results and reported Jev usage are retained in the computer's session receipt; audio is not retained. Jev usage remains separate from agent usage.

Text, web addresses, key names and app names must come from the command itself. Ambiguous controls and apps require a numbered choice. Destructive actions require confirmation. Voice typing refuses password and other recognized sensitive controls; use the remote keyboard for those. Without readable controls Øphio can't tell a password field, so speak only what you would type on the remote keyboard. Each action checks the current control identity and position again, and a key or text meant for one window is refused once another window has focus (on Hyprland and Sway, which say which window has focus).

Browser control uses an isolated Chromium profile and inherited CDP pipes, with no debugging TCP port. Ending automation leaves that browser window open. Closing the window removes its profile, with any cookies and sign-ins, once the browser and its helpers have exited. Profiles of windows that closed while Øphio was not running are removed when it next starts; one a running process still uses is kept. DOM observations include same-origin frames and safe accessibility labels. The driver does not automate cross-origin frames in this version.

The ordinary input lease and local Stop indicator also protect voice sessions. Stop, local Stop, lock, revocation, heartbeat expiry and ten minutes of inactivity end input authority. Sessions also stop after repeated unchanged observations, 100 recorded steps or a bounded receipt size. A cancelled native action remains tracked until its input barrier completes; missing confirmation is recorded as unknown and is never retried automatically.

Linux accessibility uses AT-SPI; Windows uses UI Automation. OCR is not implemented. Automated qualification uses synthetic accessibility replies and a real headless Chromium against loopback fixture pages. Windows native execution and a provisioned Linux desktop guest still require qualification; a successful cross-compile is not runtime evidence.
